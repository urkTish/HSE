# Decisions

| # | Date | Decision | Why |
|---|---|---|---|
| 1 | 2026-10-05 | All phases are developed on one working branch (`claude/hse-platform-build-kannxy`) instead of `phase-<n>/<module>` branches; each phase is a reviewable set of commits. | The session can only push to its designated branch. |
| 2 | 2026-10-05 | Audit log append-only is enforced by a DB trigger; the only delete path is the `hse_audit_purge()` SECURITY DEFINER function. A restricted `hse_app` role (if present) gets INSERT/SELECT only. | Spec rule 36; works even when the app connects as table owner in dev. |
| 3 | 2026-10-05 | Audit hash chain verification accepts sequence gaps only where a `retention_purge` entry recorded the purged sequence ranges. | Per-project retention leaves gaps in the global chain; unrecorded gaps (manual deletes) are still detected. |
| 4 | 2026-10-05 | Audit entries that must survive a failed request (`access_denied`, `login_failed`) are queued and written after rollback by the DB dependency. | A 404/401 response rolls back the request transaction. |
| 5 | 2026-10-05 | Sessions are stored server-side (`user_sessions`) and checked on every request; the JWT carries only user and session ids. | Rules 4 and 7 (idle timeout, revocation within 60 s). |
| 6 | 2026-10-05 | Lockout responds `ACCOUNT_LOCKED` only when the password is correct; otherwise the generic `INVALID_CREDENTIALS`. | AC3 needs a locked response; this leaks the least to guessers (rule 3). |
| 7 | 2026-10-05 | HSE Officers see the whole contractor register (with contacts); other roles see contractors engaged within their scope. | Officers onboard contractors (capability 5) before any engagement exists. Open question logged. |
| 8 | 2026-10-05 | Site restrictions (`site_ids`) on an assignment limit site/zone records for every role, not only S-scope roles. | Rule 11 is stated for any assignment. |
| 9 | 2026-10-05 | Duplicates return 409 `DUPLICATE_VALUE` (with field errors); expired invite/reset links return 410. | Conflict vs validation; the frontend shows field errors either way. |
| 10 | 2026-10-05 | Zone airside attributes are a nested `airside` object in the API, stored as flat nullable columns. | Clean typing for the frontend; rule 19 becomes 'object present iff airside'. |
| 11 | 2026-10-05 | SoD (rule 16) is checked before the employer/engagement rule (29). | AC13 expects `SOD_CONFLICT` regardless of employer data. |
| 12 | 2026-10-05 | Emails go to an `email_outbox` table (EN/AR by recipient language); no SMTP sender yet. | No provider decided; keeps flows testable. |
| 13 | 2026-10-05 | Hijri dates are formatted by the frontend (ICU islamic-umalqura); the backend stores `show_hijri`/`hijri_calendar` only. | Display concern (rule 34, K3). |
| 14 | 2026-10-05 | Breached-password list: SecLists 10k-most-common (MIT) in `backend/app/data/`. | Rule 2. |
| 15 | 2026-10-05 | Typeface IBM Plex Sans + IBM Plex Sans Arabic, self-hosted via `@fontsource` packages (no Google Fonts at build or run time). | Matching Latin/Arabic metrics; works offline/on restricted site networks and in CI without font downloads. |
| 16 | 2026-10-05 | Theme preference (light/dark/device) is stored per device in `localStorage` (`hse.theme`), not on the user profile. | A viewing convenience (office screen vs phone outdoors); no contract change needed. |
| 17 | 2026-10-05 | On phones (< 768 px) data tables render as labelled cards; controls are 44 px on touch screens and compact only with a mouse on ≥ 1024 px. | Field use with gloves/sunlight; desktop density preserved. |
| 18 | 2026-10-06 | AI-8 (default pending the HSE Manager): the backend computes no trend direction. The AI quotes the values and the comparison deltas the API returns; trend wording only when a series has `trend_established = true` (≥ 6 monthly points with man-hours). | Coordinator answer (1); avoids invented statistics. |
| 19 | 2026-10-06 | D-10 PDF export is deferred and parked in PROGRESS (default pending the HSE Manager). | Coordinator answer (2). |
| 20 | 2026-10-06 | Observation, inspection and CA visibility (default pending the HSE Manager): incident-register scope via capability 31, plus records the user owns or must verify. | Coordinator answer (3); the matrix has no explicit row. |
| 21 | 2026-10-06 | `scope_narrowed` in KPI responses is true whenever the role scope reduced the request, including an unfiltered request from a scoped user (e.g. a Permit Receiver sees one contractor). AI tool results report `scope_narrowed` only when an explicit request was reduced, so the model does not refuse the user's own scope. | D-3 / AI-4; frontend report. |
| 22 | 2026-10-06 | Leading warning E4 'repeat event' = a recordable case with the same mechanism in the same tier-1 tree within 90 days. HiPo is ≥ 2 HiPo events in the month. | §6.9 leaves 'repeat' undefined. |
| 23 | 2026-10-06 | The AI data notes (completeness, provisional cases, low exposure, restatements, no access) and the Sources block are appended by the server, not left to the model. Recommendations come in a fenced `recommendations` JSON block, which the server orders by the hierarchy of controls and checks (≥ 1 engineering-or-higher control, sources cited); a violation triggers the one regeneration. | AI-3, AI-7, AI-11 become checkable. |
| 24 | 2026-10-06 | Insights are rule-based (previous-period deltas from the engine, leading warnings, data quality, LTI-free milestones). AI narrative items are added only with a key and are dropped if they fail grounding. | Works without a key (AC75); no invented figures. |
| 25 | 2026-10-06 | Monthly-report 'revised since publication' compares a hash of the figures re-rendered as of month end with the hash frozen at publication. A refusal stop reason is treated as `AI_UNAVAILABLE`. | `service.snapshot` hashes all facts, so it would flag unrelated later months. |
| 26 | 2026-10-06 | Seed: the named incident refs from A.5.6 keep their reserved sequence numbers, so incident refs are not strictly chronological around them. Phase 0 seed mobilisation dates were aligned to A.2. | The A.3 volumes make chronological numbering impossible with those refs. |
| 27 | 2026-10-06 | The DLIFT seed writes `no_work` rows (0 h) after its 2026-08-15 suspension; the engagement stays expected in completeness. | A.2: no hours after suspension; the contractor is suspended, not demobilised. |
| 28 | 2026-10-06 | Corrective-action verifier ≠ owner is checked at the verify transition (`VERIFIER_IS_OWNER`) as well as at creation. HSE meetings use the inspection-plan capability (33) until the matrix names one. | Owner can change after creation; the matrix has no meeting row. |
| 29 | 2026-10-06 | When a case's derived category changes after it was confirmed without an override, the confirmation is reopened (back to provisional); an overridden category is kept. An incident can be quick-closed only when all its cases have a confirmed classification. | Keeps K-values free of provisional cases on closed incidents. |
| 30 | 2026-10-07 | Phase 2 contract: ADP and AVP applications are the permit record itself in `validity_status = pending` (then `…/issue` → active, or `…/withdraw` → withdrawn); there is no separate application entity. | Spec §4.5 starts at Active; capabilities 60/63 (apply) and 61/64 (issue) need a pre-issue state. |
| 31 | 2026-10-07 | Suspend / confirm / reinstate / revoke / return / loss for inductions, passes, ADPs, AVPs and access cards share one endpoint family `/credentials/{kind}/{id}/…` returning `CredentialState`. WAP and worker status changes stay on their own transitions. | §5.9 defines one lifecycle model; one UI component serves every credential. |
| 32 | 2026-10-07 | Gate devices log in with a device token (shown once at registration) and get a separate session (`hse_gate_session` cookie or Bearer). Any non-gate endpoint called with it returns 403 `GATE_DEVICE_FORBIDDEN`. | GC-1 and AC66 (403, not 401). |
| 33 | 2026-10-07 | The error envelope gains an optional `detail.meta` object (e.g. WORKER_EXISTS → worker_no, VALIDITY_EXCEEDS_LIMIT → limiting_factor, WAP_BLOCKED → blockers). | WK-2 and AP-6 require returning the existing worker_no or the limiting field. |
| 34 | 2026-10-07 | Phase 2 workers use their own enums `WorkerIdType` (adds gcc_id) and `WorkerPersonType` (no third_party_public). Phase 1 injury-case enums are unchanged; a gcc_id worker linked to an injury case leaves the case's id_type empty. | Avoids changing Phase 1 validation rules. |
| 35 | 2026-10-07 | Worker ID search is `POST /workers/lookup` (exact match on the blind index), not a query parameter. | Keeps full ID numbers out of URLs and access logs (WK-3, P2-2). |
