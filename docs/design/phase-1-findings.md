# Phase 1 design pass: UX findings

Scope: the Phase 1 screens — dashboard home (filters, headline band, tiles, sparklines, charts C1–C9, pyramid, league table, action panel, due-soon list, insights), drill-down dialog, AI assistant panel, monthly reports (list, detail, print view), workforce returns and import, month lock, incidents / injury cases / investigation, observations, inspections and plans, corrective actions, HSE meetings and HSE settings. Shared components were changed only where a Phase 1 screen needed it, and stay consistent with Phase 0.

Method: the app ran against the real backend (local Postgres, `app.seed`). I signed in as Faisal Al-Harbi (HSE Manager) and used September 2026 (`?period=month&anchor=2026-09-15`). Playwright took screenshots in EN and AR, desktop (1366) and mobile (390), light and dark. The dashboard was captured in all 8 combinations; the other screens in 4 (EN desktop light, AR desktop dark, AR mobile light, EN mobile dark). The AI panel used the recorded stream `frontend/e2e/fixtures/ai-stream.ts` through route interception (no API key). The seed has no monthly report, so for the print view I rendered the real September tables into the dev database with the backend's own `reports.render()` and a placeholder narrative (dev data only; the e2e database is rebuilt on every run).

Screenshots (`docs/screenshots/phase-1/design/`, 12 files): 01/02 dashboard first screen EN desktop light, 03/04 dashboard first screen AR phone light, 05/06 pyramid + league table (+ insights after), 07/08 drill-down AR desktop dark, 09/10 incident register EN desktop, 11/12 print view page 1 EN and AR (from the PDF). The full audit set (≈ 150 images) was not committed to keep the repo small.

Effort: **S** < 1 h · **M** ≤ 1 day · **L** a redesign that needs the user's approval.

Not changed on purpose:
- KPI values, comparisons, targets and RAG come from the backend `display` strings exactly as before. Thousands grouping is applied only to raw record decimals (man-hours, drill numerator/denominator), never to KPI displays.
- Seven categorical colours in C3 "Events by type" (8 event types, stacked) stay: the legend and table carry identity. Series 8 is red there ("Environmental"); it is a categorical hue, not a status, but see doubts.
- Red buttons for void / cancel / reject stay (hard-to-undo actions, Phase 0 rule).
- No business logic, API calls, permissions or data were changed; e2e selectors are unchanged.

## Design system additions (Phase 1)

- **Chart colour map** (in `chart-renderer.tsx`, `seriesColor(role, key)`): the same entity has the same colour on every dashboard chart; status colours are never series colours.
- **Ordinal ramp** for ordered categories (pyramid): one hue, `color-mix(in oklab, var(--series-1) N%, var(--surface))`, darkest = most severe.
- **Delta tone**: better = success, worse = warning (amber), neutral = muted; direction is always also an arrow and a sign.
- **Status badge keys** added: `month_open`, `month_locked`, `risk_high`, `risk_medium`, `risk_low`, `hipo`.
- **Print**: `@media print` in `globals.css` forces light tokens, A4 margins with page numbers, repeated table headers; a page can add a print-only header (`hidden print:block`) and a fixed footer (`.report-print-footer`). Permits (Phase 3) should reuse it.
- **Lists**: `ListToolbar` folds filters after the 4th on desktop; codes in tables don't wrap.
- **Bilingual print strings**: `reports.printDoc.*` values hold "EN|AR" in both locales, so the print header shows both languages whatever the UI language.
