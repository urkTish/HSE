# Phase 2 design pass: UX findings

Scope: the Phase 2 site / airport access screens — the gate check screen (`/gate`: scanner, verdicts GRANTED / GRANTED_WITH_WARNING / DENIED / PENDING_* with countdown, admitted despite denial, device sign-in, offline), workers (masked ID and unmask dialog, deployment, access card), inductions (signature pad), zone profiles, airport pass setup / applications / passes, ADPs and offences, vehicles, AVPs and sticker, NOTAM requests, obstacle clearances (live preview), WAPs (board, print, ops events), credential lifecycle actions, gates and devices, access settings, gate log, and the dashboard access band with charts C10–C12. Shared components were changed only where a Phase 2 screen needed it and stay consistent with Phases 0–1.

Method: the app ran as a production build against the real backend on a fresh, migrated and seeded database (`hse_design`, `app.seed` incl. the Phase 2 seed). I signed in as Faisal Al-Harbi (HSE Manager) on ANIA-EXP and used the gate screen as a user with `gate.check` on the seeded gates G-ANIA-01 (site gate) and G-AAP3 (airside, three zones). Real verdicts came from seeded subjects while WAP-0031's night window was open: GRANTED (WKR-000001 at the main gate), GRANTED_WITH_WARNING (WAP-0031 crew at Z-TWB, `HOOK_NOT_AVAILABLE`), DENIED with one to five reasons (VEH-0003; WKR-000001 at Z-APR-21), PENDING_ESCORT (WKR-000004). Playwright took the gate in all 8 combinations (EN/AR × desktop 1366 / phone 390 × light/dark) and 36 other screens in 4 (EN desktop light, AR desktop dark, AR phone light, EN phone dark), plus print-media renders and PDFs of the access card, AVP sticker and WAP print. The HSE Officer and Contractor HSE Rep views were covered by the existing e2e role tests; this pass did not change any role-dependent rendering. I loaded the dataviz guidance before touching C10–C12.

Screenshots (`docs/screenshots/phase-2/design/`, 12 files): 01/02 gate "granted with a note" EN phone light, 03/04 gate DENIED (5 reasons) AR phone dark, 05/06 access card (screen before, print after), 07/08 WAP print (EN screen before, AR print after), 09/10 AVP sticker, 11/12 C11 denial reasons in Arabic.

Effort: **S** < 1 h · **M** ≤ 1 day · **L** a redesign that needs the user's approval.

Not changed on purpose:
- The verdict colours themselves (GRANTED green, GRANTED_WITH_WARNING amber, DENIED red, PENDING blue) follow the spec and the frontend notes; only their presentation changed. Verdict panels are identical in light and dark mode on purpose (a gate tablet should always look the same).
- Reason codes (e.g. `WAP_MISSING`) stay visible in small muted text under each reason: the guard can read them to the HSE Officer on the phone.
- Red buttons for ban worker, demobilise, refuse, withdraw and suspend stay (hard-to-undo actions, Phase 0 rule).
- No business logic, API calls, permissions, KPI values or data were changed; no data field was added to or removed from any screen (the WAP print now shows both scope languages, both of which the page already loaded). All e2e selectors are unchanged.

## Design system additions (Phase 2)

- **Verdict tokens** (`--verdict-granted | note | denied | pending | neutral` and `-fg`), theme-independent solids for full-screen results. Use them only for gate/scan verdicts, never for badges or charts.
- **Notes vs warnings**: a check that cannot run yet (`HOOK_NOT_AVAILABLE`) is a neutral note with an info icon. Amber is for things that are actually at risk (expiring, escorted, blockers).
- **Thumb bar**: on one-handed screens the result actions live in the fixed bottom bar; the content reserves the bar's measured height.
- **Print documents**: `AccessPrintHeader` (`wide` A4, `narrow` sticker, `card` ID-1) + `BiLabel` + `accessPrint.*` "EN|AR" strings; `.paper` keeps light tokens on paper surfaces. Phase 3 permits should reuse them together with the Phase 1 `@media print` rules.
- **Charts**: horizontal bars keep their order in RTL (largest first); only vertical/time axes mirror.
- **Status badge key** `granted_note` (amber with a tick).
