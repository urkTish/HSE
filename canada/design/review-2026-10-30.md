# Design review — Agent 05 map skeleton, 2026-10-30

Reviewer: Agent 06. Scope: everything in `map/` at the time of
review: `DATA-SOURCES.md` and the app in `map/app/` (source in `src/`,
production build served with `vite preview`) and `map/ARCHITECTURE.md`,
which appeared near the end of the review and was read in full. The app was
rendered in Chromium at 1440 × 900 (light and dark) and 360 × 740 (light), and
exercised by keyboard (search → select → Tab). Reference: `design-system.md`,
`components.md`, `wireframes/`.

**Score: 6.5 / 10.** A disciplined, honest skeleton: tokens adopted as-is,
provenance and withheld figures handled correctly, a climate chart that
already follows almost every rule. What holds it back is map legibility
(layers are told apart by colour alone, and several share one colour), the
keyboard path, the mobile layout, and an information hierarchy that lets
market records masquerade as nearby places.

Severity: **Critical** blocks a user or breaks a SPEC rule · **Major**
causes real friction or an accessibility failure · **Minor** inconsistency ·
**Polish** craft and character.

---

## What is working (keep it)

1. `src/index.css` imports `design/tokens.css` and `design/tailwind-theme.css`
   unchanged and defines no colours of its own; every utility in the
   components is a token (`bg-surface-1`, `text-ink-3`, `shadow-3`…).
2. Climate chart (`src/ui/ClimateChart.tsx`): three small multiples on one
   month axis, no dual axis, temperature split at a 0 °C reference line,
   hatched null months, period, station, climate ID, elevation, distance and
   source visible under the chart, a "not a forecast" line, and a table
   twin, keyboard month reading and honest notes for older periods and
   distant stations. This is the right chart.
3. Honesty: money figures withheld from static files and explained
   ("The figure itself is not stored in the map"), schools filtered to
   `qualifying`, empty layers carry their own `emptyNote`, base-map failure
   falls back to a no-network style with a notice.
4. Attribution strings come from `DATA-SOURCES.md` via `attribution.json`,
   and are filtered to the layers in use.
5. Reduced motion respected for `flyTo` and cluster zoom (`jumpTo` /
   duration 0). Search is a correct WAI-ARIA combobox.

## Findings

### F-01 · Critical · Layers are distinguishable by colour only, and several share one colour
- **Where:** `src/map/MapView.tsx`, `addOverlays()` → layer `ce-<id>-pt` (every point layer is a `circle`);
  `src/ui/LayerPanel.tsx` row swatch `rounded-full` (round colour swatch);
  `src/kb/layers.config.json` (no shape field).
- **What:** All twelve layers render as the same dot. Parks, trails and
  natural attractions are the identical green; tourism and transport the
  identical grey; cities and neighbourhoods the identical ink. With two of
  them on, the user cannot tell which marker is which, and colour-blind users
  cannot separate even the different hues reliably (the four domain hues were
  validated *on the condition* that shape carries identity —
  design-system §4.3, §7.2). Fails WCAG 1.4.1 and design-system principle 7
  (shape before colour) for the map's core job.
- **Fix:** Add `shape` and `minzoom` to each layer in `layers.config.json`
  (table in `components.md` §2). Render points as a `symbol` layer whose
  `icon-image` is a runtime-drawn marker (`MarkerGlyph`: fill = layer token,
  1.5px `--ce-marker-stroke` ring, 2px `--ce-marker-halo`; `map.addImage(id,
  imageData, { pixelRatio: 2 })`, regenerate on theme change). Use the same
  `MarkerGlyph` as inline SVG in the layer panel so legend and map always
  match. Keep a `circle` layer underneath only for the `feature-state` hover
  ring.

### F-02 · Major · No keyboard path to map features; focus is not managed around the profile
- **Where:** `src/map/MapView.tsx` (markers exist only on the canvas);
  `ProfilePanel` root `<aside>` (no focus handling); `src/App.tsx` global `keydown` Escape handler.
- **What:** (a) A keyboard or screen-reader user can reach a place only by
  already knowing its name for search; nothing lists what is on the map. (b)
  After selecting "Vancouver" from search, focus stays in the search input;
  the profile is not announced and Tab goes to the layer panel, not the
  profile. Closing the profile does not return focus. (c) The global Escape
  handler closes the profile even when Escape was meant to close the search
  list.
- **Fix:** Add `PlacesInViewList` (components §2): ≤ 50 buttons updated on
  `moveend`, reachable via a skip link. On profile open, focus the place
  heading (`tabIndex={-1}`) and announce "Vancouver, British Columbia,
  selected" through one live region; on close, return focus to the element
  that opened it. In `SearchBox`, `e.stopPropagation()` on Escape, and make
  the global handler ignore events from inputs.

### F-03 · Major · Market observations are listed as "Nearby" places at 0.0 km
- **Where:** `src/ui/ProfilePanel.tsx`, `RecordProfile` → `near = nearby(…, index.records, 50, 8)` and the "Nearby in the knowledge base" section.
- **What:** The Vancouver profile's first substantive section is five
  "MLS® HPI 'GREATER_VANCOUVER' — apartment benchmark price…" and "CMHC
  average rent…" rows at 0.0 km under "Nearby in the knowledge base".
  These are data about the city, not places near it. They push geography and
  climate down, read as noise, and invite the user to click into
  figure-less records. SPEC §9 B puts them under "Residential intelligence".
- **Fix:** Exclude non-place categories (`re`, `nat`, `clim` already linked,
  `hazard` unless it has a footprint) from `nearby()`. Add a "Living" section
  (`MarketObservationList`, components §3) on city and neighbourhood profiles
  that groups `re` records by metric, shows period, figure kind and source,
  and offers `OnDemandFigure` for the value. Order sections as in
  wireframe 03: About → Geography → Climate → Living →
  Schools → Nature → Nearby → Location → Sources.

### F-04 · Major · Mobile layout: chrome covers about half the map
- **Where:** `src/App.tsx` header and layer-panel containers; `src/index.css` small-screen rule;
  `MapView.tsx` attribution effect (`AttributionControl({ compact: true })`).
- **What:** At 360 × 740 the wordmark card, the search field and the Layers
  card stack to about 190px at the top, and the attribution box opens
  expanded over about 170px at the bottom. The zoom buttons sit under the
  wordmark card. Southern Ontario cities overlap into one blob at the initial
  zoom.
- **Fix:** Below 768px follow wireframe 06: one row with a search pill and a
  48px Layers button (wordmark hidden; it is in the page title), layers in a
  full-screen sheet, controls bottom-right above the sheet, profile in a
  bottom sheet with snaps 148px / 50% / 92%. Start the attribution collapsed
  on mobile (after adding the control, remove `maplibregl-compact-show` from
  its container when `innerWidth < 768`) — it stays one tap away. Apply city
  `minzoom` tiers (F-01 config) so only tier-1 cities show at country zoom.

### F-05 · Major · Dark mode: MapLibre controls and attribution are nearly invisible
- **Where:** `src/index.css` MapLibre control overrides; `MapView.tsx` `NavigationControl` / `ScaleControl`.
- **What:** In dark mode the zoom buttons' icons (MapLibre's dark SVG
  background images) are black on `--ce-surface-1`, and the attribution text
  renders at very low contrast; both fail SC 1.4.11 / 1.4.3.
- **Fix:** Replace `NavigationControl` with `MapControls` (components §2:
  Lucide `Plus`, `Minus`, `Mountain`, `RotateCcw` in `currentColor`). Until
  then, under both dark selectors add `.maplibregl-ctrl-icon { filter:
  invert(0.9); }` and raise specificity so the attribution colour wins over
  MapLibre's stylesheet, which is imported later from `MapView.tsx`
  (`.maplibregl-ctrl.maplibregl-ctrl-attrib, .maplibregl-ctrl-attrib a {
  color: var(--ce-ink-2) }`).

### F-06 · Major · City names are drawn twice
- **Where:** `MapView.tsx` layer `ce-cities-label` plus the base style's own place labels.
- **What:** "Vancouver", "Victoria" and "Abbotsford" each appear twice (base
  map label and our label), offset by a few pixels. It looks broken and
  doubles label density.
- **Fix:** When the cities layer is on, hide the base style's `place` labels
  for `class` in `city`/`town` (iterate style layers with
  `source-layer === "place"` and add a filter, or set them `visibility:
  none` and rely on our labels); keep villages and hamlets from the base map
  for orientation.

### F-07 · Major · The profile panel can hide the selection; the map does not re-pad
- **Where:** `MapView.tsx` focus effect (`flyTo`); `App.tsx` profile container.
- **What:** `flyTo` centres the selection on the full canvas, so at
  1024–1279px the 440px panel covers it, and the selection ring sits under
  the panel. Initial `fitBounds` padding is applied once and never updated.
- **Fix:** Pass the panel width to `MapView` and call
  `map.setPadding({ right: panelOpen ? panelWidth + 12 : 0, left: railWidth
  })` whenever the panel opens, closes or resizes; `flyTo` then centres in
  the visible area (design-system §6.1).

### F-08 · Minor · Provenance is pooled at the bottom of the profile
- **Where:** `ProfilePanel.tsx`, section "Sources and reliability".
- **What:** Source, period and verification appear once, under "Sources and
  reliability", far from the facts they support. The climate chart already
  carries its own provenance line, which is the pattern to extend.
- **Fix:** Implement `SheetMargin` (components §3) and end every evidence
  section with it; keep the full source list at the bottom.

### F-09 · Minor · Absence is silent
- **Where:** `ProfilePanel.tsx` header comment ("a section with no data is not rendered
  at all").
- **What:** Hiding empty sections is right, but the user cannot tell "no
  schools here" from "not yet researched".
- **Fix:** End the profile with `NotYetResearched` ("Not yet researched for
  this place: Schools · Trails · Healthcare").

### F-10 · Minor · Hover tooltip is a live region
- **Where:** `MapView.tsx` hover tooltip `<div … role="status">`.
- **What:** Screen readers announce every name the pointer crosses.
- **Fix:** `aria-hidden="true"` on the tooltip; announce selection only.

### F-11 · Minor · Climate chart: two details left
- **Where:** `ClimateChart.tsx` month-axis `<text>{m[0]}</text>` and `fmt()`.
- **What:** While this review was being written Agent 05 added arrow-key
  month reading with a live region, a baseline tick for zero, the "Older
  period" note and the station-distance note — all resolved. Two remain:
  (a) month labels are single letters (J F M A M J J A S O N D), ambiguous
  three times over, though the panel is wide enough for "Jan"; (b) negative
  values use a hyphen-minus instead of the true minus sign.
- **Fix:** (a) Three-letter months when the column is ≥ 26px (reference:
  `renderClimate` in `wireframes/03-city-profile.html`). (b) Replace `-`
  with U+2212 in `fmt`.

### F-12 · Minor · Layer rows are 32px tall
- **Where:** `LayerPanel.tsx` row `<label className="flex min-h-8 …">`.
- **What:** Passes WCAG 2.5.8 (24px) but misses the product's 44px target
  (design-system §12), and the rows are the most-used control.
- **Fix:** `min-h-11`; the visual row can stay compact with padding.

### F-13 · Minor · Developer telemetry in the user interface
- **Where:** `LayerPanel.tsx` footer paragraph.
- **What:** "187 records, 111 on the map. Validator: 187 record(s) checked,
  0 failed…" is useful to agents, noise to the user.
- **Fix:** Move it to `AboutDataDialog` (components §1).

### F-14 · Polish · The product has no typographic identity yet
- **Where:** `DATA-SOURCES.md` line 35 (system font stack only);
  `ProfilePanel.tsx` `RecordProfile` header `<h2 className="… text-2xl …">`.
- **What:** With system fonts and a 32px title, the screen passes the
  brand-swap test for any map app; nothing says "atlas".
- **Fix:** Add `@fontsource-variable/archivo` and
  `@fontsource-variable/source-sans-3` (fonts SIL OFL 1.1, packages MIT;
  self-hosted, no CDN) with a `DATA-SOURCES.md` line each; use
  `font-display` + `text-display` + uppercase + `wdth` 112 for the place
  name in `ProfileHeader`. Tokens already name these faces first, so nothing
  else changes.

### F-15 · Polish · Province selection lacks dimming and breadcrumb
- **Where:** `MapView.tsx` `ce-prov-fill` / `ce-prov-line`; `App.tsx` (no breadcrumb).
- **What:** Selecting a province outlines it correctly, but other provinces
  stay at full strength, there is no "where am I" trail, and no camera move.
- **Fix:** `fitBounds` to the province, dim others (fill
  `--ce-map-region-hover-fill` at 40% opacity outside the selection), and add
  `Breadcrumb` (Canada › Province › City).

## Architecture (`map/ARCHITECTURE.md`)

Sound and well separated: data build → static files → `kb/`, `map/`, `ui/`,
`dynamic/`; money figures withheld at build time; schools filtered twice;
tokens read into MapLibre at style load. Two sequencing objections:

- **A-1 · Major.** The Phase 2–4 plan puts marker shapes, the selection
  bracket and the mobile bottom sheet in Phase 3. Shapes (F-01) and a keyboard
  route to features (F-02) are correctness, not polish: they decide whether
  layers can be told apart at all. Move them to the next iteration, before
  more layers fill with records from Agents 03 and 04.
- **A-2 · Minor.** The validator summary is planned to stay in the layer
  panel; move it to "About the data" (F-13).

## Risks in the information hierarchy (SPEC §9 B–D, not yet built)

| Risk | Why it matters | Mitigation (designed) |
|---|---|---|
| Comparison arrives as a scoring table | SPEC §4 forbids decimals without range; users read rank as truth | Wireframe 04: bands, meter, "No data", weights banner, gate badges, sensitivity |
| Concept search silently drops criteria it cannot evaluate | The user believes "mild winters + schools" was applied | Wireframe 05 B: criteria chips naming record categories; "No data never counts as a match" |
| User-dependent criteria filled with guesses (budget, child ages) | SPEC §0: the system must not assume the user | Chips stay dashed and unapplied until the user sets them |
| Province panel drifts into provincial averages | SPEC §8 B and principle 3 | Wireframe 02: regions and stations listed, never one number |
| On-demand prices shown without date | SPEC §2.7, §9 B | `OnDemandFigure` states, 60-day stale badge |
